# ADR 0015 — Investigation provider: mock by default, Ollama recommended, one generic client

- Status: accepted
- Date: 2026-10-12 (provider terms checked on this date)

## Context
Day 3 adds an LLM-written investigation. CLAUDE.md requires that no real provider becomes
the default until its API terms, pricing and free-tier limits are checked and recorded,
that tests and CI work with no key and no network, and that the provider sits behind a
small replaceable interface. The investigation sends incident data to the provider, so
where that data goes, who keeps it and what it costs must be explicit.

## Decision
1. **The default provider is `MockProvider`** (`SENTINEL_LLM_PROVIDER=mock`): deterministic
   templates that cite real fact ids, no network, no key. The UI labels its output
   "generated by fixed rules, not a language model". Tests and CI only ever use it, or
   fakes over `httpx.MockTransport`.
2. **One generic real client**, `OpenAICompatibleProvider`: a single `POST
   {SENTINEL_LLM_BASE_URL}/chat/completions` with `httpx`. It does not depend on
   `response_format` (support differs between providers); the validator checks every reply
   instead. Swapping providers is configuration, not code.
3. **Recommended real provider for development and demos: Ollama, running locally.** No
   API key, no per-token cost, and the incident data never leaves the machine, which
   removes retention and training questions entirely.
4. Hosted OpenAI-compatible providers (Groq, Mistral, ...) can be configured the same way,
   **after** the operator re-checks the items marked unverified below for their account.

## What was verified (official sources, 2026-10-12)

| Provider | Verified | Source |
|---|---|---|
| Ollama | OpenAI-compatible `/v1/chat/completions`; local base URL `http://localhost:11434/v1`; `response_format` listed as supported; locally the API key is required by OpenAI clients but ignored | [docs.ollama.com/api/openai-compatibility](https://docs.ollama.com/api/openai-compatibility) |

| Mistral | A free API mode exists with the lowest rate limits, intended for evaluation and prototyping; limits are per account in the console | [help.mistral.ai: rate limits](https://help.mistral.ai/en/articles/698531-why-am-i-hitting-api-rate-limits-and-how-do-i-increase-them) |

## Not verified (do not rely on these without checking)
- **Groq free plan limits.** The official rate-limit page shows values for
  `openai/gpt-oss-20b` (30 requests/min, 1K requests/day, 8K tokens/min, 200K tokens/day)
  but states they are the Developer plan's base limits. Whether a free plan applies to an
  account, and with which limits, is only shown in that account's console.
- **Groq training use** of API data: the data page does not say either way.
- **Mistral free-tier training default** (opted in or out by default): not stated on the
  pages above; third-party sites claim opt-in by default. Check the Privacy toggle before
  sending any data.
- **Mistral OpenAI compatibility and small-model prices**: not confirmed from an official
  page on this date (the pricing page lists no small-model API prices).
- **Ollama model quality and speed** on a given machine: depends on the model and the
  hardware; small local models follow strict JSON less reliably (the validator and the
  single retry are designed for that).

## Data sent to the provider
The evidence bundle only (`investigation/bundle.py`): incident identity (id, title,
severity as read-only context, resource name and id, region, rule ids, times), fact
statements and values, and the timeline. No raw time series, no credentials. Free text
(deployment labels now, log samples from Day 5) is clipped to 300 characters and placed
in a block declared as data. In AWS mode (Day 5) resource names and instance ids would go
to a hosted provider; the AWS account id is masked by rule. With Ollama nothing leaves
the machine.

## Cost controls
LLM calls happen only on `POST /incidents/{id}/investigation`, never on sync or any GET
(tested). At most two calls per click (one retry for invalid output), `max_tokens`
capped (`SENTINEL_LLM_MAX_TOKENS`, default 1500), a timeout, and one investigation per
incident at a time. No automatic runs.

## Alternatives considered
- **A hosted provider as default** (Groq, Mistral): better models than a small local one,
  but sends data off the machine and depends on terms that could not all be verified.
- **A provider SDK or an LLM framework**: forbidden by the dependency policy, and the
  integration is one HTTP request.
- **Relying on `response_format: json_schema`**: not portable across providers; the
  validator is needed anyway, because a schema does not prove that citations exist.

## Consequences
- The product is fully usable and demonstrable with no account, no key and no cost.
- A real model is one environment change away; its terms must be re-checked by whoever
  configures it, because the unverified items above can differ per account and change
  over time.
- Real-provider runs are manual and saved in `docs/examples/`; automated tests never
  call one.
